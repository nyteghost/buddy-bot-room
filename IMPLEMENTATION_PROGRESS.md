# Implementation progress (branch `upgrade/local-first`)

Image for this branch: `ghcr.io/nyteghost/buddy-bot-room:beta` (main stays on `:latest`).

## Review findings (what already existed)
- Accounts + login (`accounts.server.ts`, `gate.server.ts`); keys are server-side and write-only (`settings-crypto.server.ts`).
- Memory/embeddings (`rag.ts`, `embed*.ts`), hardware/GPU tiers (`hardware.server.ts`, `gpu-tier.ts`), Ollama catalog (`model-catalog.ts`, `ollama.server.ts`), Unraid watcher (`unraid.server.ts`), backups, Tailscale.
- All model calls go through exactly two server files: `chat.server.ts` (rooms) and `ask.server.ts` (scheduled/Telegram questions). The browser sends the engine choice (and, for cloud engines, its own key) with each request.
- `room.tsx` is ~2,000 lines; `engine.ts` holds engine settings; no approval/audit system exists; no per-agent model assignment (the `model` on each agent is a legacy label).

Tests: 7 (cleaning, theme scope, memory visibility, prompt text).
- [x] R3-15 Project workspaces (lightweight): Notes panel -> Projects. A project has an objective, status (active/paused/done), assigned pals, tasks with "waits for" dependencies (loops refused), saved decisions, next steps, relevant documents and a run history. While a project is active: a short brief (objective, team, open tasks, decisions, next steps; max 800 chars) goes in front of the pals together with the project's memories; its assigned pals are seated (also right after a restart); if it lists documents only those are searched; each finished discussion adds a history line (question, mode, pals, first 200 characters of the last answer). Reuses existing systems: project memories stay in the workbench, a task can be copied to the normal to-do list, documents are the existing document store. Stored in `pixel-pals-projects-v1` (backups and account sync). Not built on purpose: Gantt/boards, assignees per task, time tracking. Limits: history keeps the latest 30 runs; "discussion history" is this run log, not a link to saved chats. Tests: 7.
- [x] R3-16 Ollama benchmarking: Settings -> Local AI -> Benchmark runs a fixed chat/code/reasoning set on an installed model and stores real measurements (time to first token, tokens/s, prompt speed, load time, GPU memory, wait outside Ollama, failures) in `BUDDY_DATA_DIR/ollama-bench.json`. Unmeasurable values stay `null`. Results feed back: models that failed half the time or ran under 5 tokens/s (3+ runs) are skipped by Automatic choice when another model exists; best measured model per task is shown. Owner-only when accounts are on. No numbers from your real GPU yet (see PERFORMANCE_REPORT.md). Tests: 13.
